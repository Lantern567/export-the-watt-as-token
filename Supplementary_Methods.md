# Supplementary Methods

Reproducible methods for *"Waking the world's untapped mega-energy resources through the global token economy."* All results are regenerated by the scripts in `analysis/`, which write machine-readable results to `data/*_results.json`; figures are rendered by `figures/make_figures.py`. Run order:

```
python analysis/portfolio_demand.py        # M1  -> data/portfolio.csv, portfolio_demand_results.json
python analysis/lifecycle_cost.py          # M4  -> data/lifecycle_results.json
python analysis/gpu_constraint.py          # M3  -> data/gpu_constraint_results.json
python analysis/fetch_diurnal_wikimedia.py # M2  -> data/diurnal_kernel.json   (fits a(h); needs internet)
python analysis/temporal_matching.py       # M2  -> data/temporal_matching_results.json, temporal_profiles.json
python analysis/validate_diurnal_ai_traces.py  # M2 validation -> data/diurnal_ai_validation.json (downloads BurstGPT)
python figures/make_figures.py             # Fig 1-5, Box 1, Fig S1; Fig S2 via figS2_diurnal()
```

## S1. Portfolio and demand scenarios (M1)

**Portfolio.** We curate a tiered inventory (`data/portfolio.csv`) from a 50-site global scan (`data/sites_master.csv`), recording for each site a *strandable* energy range (TWh yr⁻¹) — the exportable/curtailed fraction with no or weak local market, **not** total generation — together with type, status, coordinates, LCOE band, and the source row. **Tier 1** = discrete stranded mega-projects (remote mega-hydro + planned desert export hubs). **Tier 2** = existing renewable fleets whose output is already curtailed today (near-zero marginal value). Rows flagged `theoretical` (e.g. the ~2,600 TWh yr⁻¹ Mongolian Gobi potential) are reported only as an upper bound and excluded from the headline "realistic" sum. Screening criteria follow Zhu et al. (ref. 8): annual capacity factor, ambient-temperature/cooling suitability, round-trip latency to fibre landing points, and distance to roads/infrastructure.

**Aggregation.** Tier sums give Tier 1 realistic ≈ 1,103–2,147 TWh yr⁻¹, Tier 2 ≈ 59–107 TWh yr⁻¹, portfolio realistic ≈ 1.16–2.25 PWh yr⁻¹.

**Demand scenarios.** Electricity scenarios are anchored to the IEA *Energy and AI* (2025) 2030 projection (~1 PWh yr⁻¹) and to ref. 8's 10× and 100× cases. Token equivalence uses energy per output token ε with measured range 0.15–120 J (central ≈ 2 J): tokens yr⁻¹ = (PWh yr⁻¹ × 3.6×10¹⁸ J PWh⁻¹) / ε. The 2025 global throughput band is 1.5–2.0×10¹⁶ tokens yr⁻¹. Results: portfolio ≈ 1.2–2.3× IEA-2030 electricity demand; ≈ 100–230× 2025 token throughput at central ε.

## S1b. Full life-cycle cost & value (M4)

For each export pathway we compute, per **source** kWh of stranded clean energy, the **net value added** = gross output value − non-energy life-cycle cost (generation busbar $0.02–0.04 + conversion capex/opex + transport/loss); the source energy itself is the stranded resource being monetised. **Electron:** delivered commodity value $0.05–0.08/kWh after 6–10% loss, minus a levelised transmission adder $0.01–0.03 → net ≈ −$0.02 to $0.05. **Aluminium:** 1 kWh → 1/(13–16) kg; gross = kg × $2.3–2.6/kg = $0.14–0.20; minus non-energy cost (alumina feedstock + smelter capex/opex + shipping, ~$1.2–2.0/kg) → net ≈ −$0.05 to $0.11. **Token:** the key identity is that the non-energy life-cycle cost per source kWh = p_elec·(1−s)/s, where s = electricity's share of compute TCO (4–7%) and p_elec ≈ $0.03/kWh — this is **independent of ε**, ≈ $0.4–0.7/source kWh. For the *net* calc, gross value per source kWh = (3.6×10⁶/ε) × price is evaluated at three coupled (ε, price) tiers (budget ε=0.5 J, $0.4/Mtok; mainstream ε=2 J, $2/Mtok; frontier ε=40 J, $30/Mtok) → net value added ≈ $1.9–3.2/source kWh across all three. The headline *gross value density* in Fig. 4a is instead a price sweep ($0.40–68/Mtoken) at efficient ε=2 J — one quantity (output price) swept, parallel in kind to the electron and metal price sweeps; the token's far wider band reflects the genuine 2–3-order spread in token prices, not a two-axis artifact. Token net is therefore of order one-to-two orders of magnitude above the electron or the metal (≈90–170×). **This multiple is fragile:** the electron and aluminium net midpoints straddle zero (electron −0.02..+0.05; aluminium −0.05..+0.11), so a small change in busbar/transmission assumptions can swing it; read it as "orders of magnitude", not as exact. The token wins **despite** the highest conversion cost (the capital intensity that becomes the chip constraint, S3). Reproduced by `analysis/lifecycle_cost.py` → `data/lifecycle_results.json`; Fig. 4.

**Token LCOT cost stack (Fig. 4b).** The token figure is a full **total-cost-of-ownership (TCO)**, not a chip-only cost. LCOT is built bottom-up per accelerator at the **facility level** (`analysis/lifecycle_cost.py` → `data/lcot_breakdown.json`). Amortised annual cost stack (USD yr⁻¹ accelerator⁻¹): accelerator + server capex **$12,500** (= $50k all-in system amortised over 4 yr; 3–5 yr range) · facility capex/opex **$6,000** · O&M / staff **$1,400** · networking / fibre **$350** · **energy** = P × 8,760 h × util (0.90) × price. Throughput is tokens yr⁻¹ = P × 3,600 × 8,760 × util / ε. At a grid price (mid ≈ $0.075 kWh⁻¹) the energy term is ≈ $1,180 yr⁻¹ and the stack totals ≈ $21,400 yr⁻¹, i.e. **chips/servers 58 % · facility 28 % · O&M 6.5 % · networking 1.6 % · energy 5.5 %** (energy 4.5–6.5 % across the $60–90 MWh⁻¹ band). At ε = 2 J (mainstream) this is LCOT ≈ $0.73 Mtoken⁻¹, and switching from grid to stranded power ($20–46 MWh⁻¹) lowers LCOT by only ≈ 3.1 %. The percentage split is **independent of ε**: both the non-energy stack and the power-based energy term are per-accelerator-per-year, so ε rescales tokens yr⁻¹ (hence $/Mtoken) but not the shares.

**Cooling is included — in two places.** (i) *Cooling electricity* sits in the energy line: the per-accelerator power **P = 2.0 kW is the facility-level draw** (range 1.7–2.7 kW), i.e. it already embeds the data-centre PUE (≈ 1.2–1.4) on top of the ~0.7–1.4 kW the silicon itself consumes, so the power drawn by chillers/CRAH units/fans is metered and priced (ref. 16; see S3). (ii) *Cooling capital and non-energy operating cost* (chillers and heat-rejection, together with the building shell and power distribution) sits in the facility capex/opex line ($6,000 yr⁻¹, ≈ 28 %). This facility figure is a **lumped** value, calibrated so the whole stack reproduces the published bottom-up inference-TCO decomposition (chips/servers ~60 % · facility ~29 % · energy 4–7 %; ref. 6) rather than an itemised chiller-by-chiller build-up — read the 28 % as "building + power distribution + cooling, combined." A hotter or drier site that pushes PUE upward shifts cost between the energy and facility lines but leaves the headline conclusions (energy ≈ 6 % of TCO; stranded vs grid power saves only ≈ 3 %) essentially unchanged, precisely because energy is a small share of TCO either way.

## S2. Hourly temporal matching (M2)

**Supply.** Hourly weather for representative sites (longitudes −102° to +138°) is the ERA5 reanalysis (Hersbach et al. 2020) accessed via the free Open-Meteo archive API for calendar year 2023 (8,760 h, UTC), cached in `data/cache_openmeteo/`. Conversions:

- *Solar PV capacity factor*: CF = clip(GHI/1000, 0, 1) × PR, with shortwave radiation GHI (W m⁻²) and performance ratio PR = 0.85.
- *Wind capacity factor*: a generic power curve on 100-m wind speed v — 0 below cut-in 3 m s⁻¹; cubic ramp (v³−3³)/(12³−3³) to rated 12 m s⁻¹; 1.0 to cut-out 25 m s⁻¹; 0 above.
- *Site output* = w_solar·CF_solar + w_wind·CF_wind (mix per site). *Hydro* (Yarlung anchor) is modelled as firm with mean CF 0.55 and ±18% seasonal modulation (no weather fetch).

Each site profile is normalised to unit mean. The **balanced portfolio** is the equal-weight mean across sites (deliberate longitudinal spread); a **strandable-weighted** portfolio (weights ∝ curtailable/strandable TWh) is reported for contrast. The **+hydro** portfolio blends in the firm anchor by its strandable weight.

**Demand envelope.** No public hourly global token-demand series exists; we *construct* one and flag it as illustrative-but-grounded. Global demand in UTC is D(t) = Σ_regions w_r · a((t + tz_r) mod 24), where a(h) is a local-hour activity kernel **empirically fitted to real hourly Wikipedia pageviews** (no longer a hand-set Gaussian; see *Diurnal kernel* below). Region (tz offset, AI-usage weight w; default "total" scenario): East Asia (+8, 0.41), Europe+Africa (+1, 0.19), N. America (−6, 0.18), South Asia (+5.5, 0.12), S. America (−3, 0.07), Oceania (+10, 0.03). The weights w are **estimated from 2025 usage data** rather than hand-set (see *Demand-weight estimation* below). The envelope is aseasonal. Its diurnal peak-to-mean ratio is ≈ 1.33 (still far flatter than any single region at 2.6–3.8), because regional peaks are staggered by longitude.

**Demand-weight estimation (Fig 2a).** No public source reports a six-macro-region token-volume split, so the weights w_r are triangulated from measured 2025 proxies and reported as two scenarios (both illustrative, order-of-magnitude). *Inputs:* Anthropic Economic Index, Sep 2025 — Claude.ai country shares US 21.6%, India 7.2%, Brazil 3.7%, usage ∝ GDP per capita (ref. 23); Similarweb, Aug 2025 — ChatGPT web-traffic shares US 15.1%, India 9.3%, Brazil 5.3%, UK 4.3%, Indonesia 3.7%, Japan 3.5%, Germany 3.4%, France 3.2%, Philippines 3.0%, Canada 2.6%, ≈ 5.8 billion visits month⁻¹, China absent because ChatGPT is blocked there (ref. 24); OpenAI/NBER WP 34255 — 18 billion messages week⁻¹, 700 million users by July 2025, fastest adoption growth in lower-income countries (ref. 25); and China's National Data Bureau — ≈ 30 trillion tokens day⁻¹ mid-2025 (≈ 1.1×10¹⁶ yr⁻¹), served almost entirely by domestic models (ref. 26). *Method.* (i) The Western-platform country shares are aggregated into the six macro-regions and normalised → the **consumer** scenario (China ≈ 0): N. America 0.25, Europe+Africa 0.28, East Asia 0.16, South Asia 0.17, S. America 0.10, Oceania 0.04 (diurnal P2M 1.21). (ii) Chinese domestic-model demand is invisible to those Western-platform proxies yet comparable in magnitude to a major Western provider; for the **total** scenario (default) China is added as ≈ 30% of global token demand to the East-Asia region and the other regions are scaled by 0.70 → East Asia 0.41, Europe+Africa 0.19, N. America 0.18, South Asia 0.12, S. America 0.07, Oceania 0.03 (diurnal P2M 1.33). *Robustness.* The routable-coincidence headline is ≈ 0.90 (clean) and 0.93–0.94 (+hydro) in **both** scenarios — i.e. insensitive to the China share across the full East-Asia range 0.16–0.41 — because coincidence depends on supply–demand timing, not on absolute regional weights. The weights remain illustrative: web-visit share ≠ token volume, vendor figures are modelled single-month estimates, and the China share (the dominant sensitivity) is itself uncertain. Reproduce with `AI_DEMAND_INCLUDE_CHINA={1,0} python analysis/temporal_matching.py`. The diurnal *shape* a(h) is now empirically fitted (see *Diurnal kernel*), not assumed.

**Diurnal kernel (Fig 2c; construction visualised in Fig S2a–c).** The local-hour activity kernel a(h) is fitted to real, open, hourly data rather than assumed. We query the Wikimedia Pageviews REST API (aggregate, all-access, agent=user; CC0; ref. 27) for the two purest single-timezone Wikipedias — ja (JST = UTC+9) and de (CET = UTC+1; February window, no European DST) — over four full weeks (Feb 2026), bin hourly views by local hour, average over the window, normalise each to mean 1, and average the two; a truncated Fourier series (K = 3 harmonics) fits the result with R² = 0.98. The empirical kernel peaks at ≈ 21:00 local with a deep overnight trough (trough/peak ≈ 0.11) — materially different from the former hand-set Gaussian (peak 16:00, trough/peak ≈ 0.47): the real peak is ~5 h later and the night trough far deeper. Cross-checks: hi (IST) and pt (BRT) reproduce the evening-peak shape; en (global, multi-timezone) is comparatively flat (trough/peak 0.60), confirming the single-timezone selection. Substituting this empirical kernel raises the global-envelope diurnal P2M to 1.33 (total) / 1.21 (consumer) from ≈ 1.13 / 1.09 under the Gaussian, and lowers +hydro coincidence to 0.93 (from 0.94); clean-only coincidence (0.90) and all storage/dispersion results are unchanged. CAVEATS: pageviews are a HUMAN web-activity proxy, not measured AI inference, and language↔region is clean only for single-timezone projects; the kernel is therefore a *conservative* diurnal shape — a genuinely batchable / latency-tolerant AI load would be flatter, not peakier — so it bounds the diurnal swing from above. Reproduce: `python analysis/fetch_diurnal_wikimedia.py` → `data/diurnal_kernel.json`.

**Diurnal kernel — explicit calculation.** Steps (script `analysis/fetch_diurnal_wikimedia.py`): **(i) per-project profile** — for each project, the local-hour profile is p̂(h) = p(h) / ⟨p⟩, where p(h) is the mean of hourly views over the 4-week window in local-hour bin h = ⌊(hour_UTC + tz_proj) mod 24⌋ (Fig S2a); **(ii) kernel** — â(h) = ½[p̂_ja(h) + p̂_de(h)], renormalised to unit mean; **(iii) analytic fit** — least-squares truncated Fourier series (Fig S2b)

&nbsp;&nbsp;&nbsp;&nbsp;a(h) = c₀ + Σ_{k=1..3} [ αₖ·cos(2πkh/24) + βₖ·sin(2πkh/24) ],

with fitted (c₀, α₁, β₁, α₂, β₂, α₃, β₃) = (1.00, −0.119, −0.519, 0.090, −0.319, −0.032, −0.100), R² = 0.98 (peak 21:00 local, trough/peak 0.11, single-region P2M 1.70). **(iv) Superposition** (Fig S2c) — the global envelope is D(t) = Σ_{r=1..6} w_r · a((t + tz_r) mod 24), normalised to unit mean (diurnal P2M 1.33). **(v) Coincidence** — routable coincidence = Σ_t min(S(t), D(t)) / Σ_t D(t), with S(t) the clean-supply series scaled to ⟨S⟩ = ⟨D⟩. **(vi) Validation curve** (Fig S2d) — the real-AI token-weighted hour-of-day histogram T(h) = Σ_{requests i : ⌊ts_i/3600⌋ mod 24 = h} tok_i (normalised to unit mean), compared with a(h) by the maximum circular Pearson correlation over the 24 phase shifts.

**Validation against real AI tokens (Fig S2d).** Because the kernel is a human-web-activity proxy, we cross-check it against a real LLM-inference trace — BurstGPT (ref. 28; 1.4 million requests over 61 days, with per-request token counts; CC-BY-4.0). The token-weighted hour-of-day curve of real AI inference has diurnal P2M **1.69 — essentially identical to the kernel's per-region P2M 1.70** — with the same broad-daytime / deep-overnight shape (phase-aligned Pearson **0.87**). BurstGPT is a single aggregated service with no geographic field and an undisclosed timezone, so only shape and amplitude are compared, not absolute phase or the per-region split. Notably, the conversation-only (human-interactive) subset is *peakier* (P2M 2.24) while the API/batch-dominated total is flatter (1.69) — directly supporting the manuscript's argument that a batchable, latency-tolerant AI load flattens the diurnal swing (so the kernel is a conservative, not optimistic, choice). Reproduce: `python analysis/validate_diurnal_ai_traces.py` → `data/diurnal_ai_validation.json`.

**Storage metric.** For a flat (24/7) load equal to mean supply, the lossless reservoir requirement is the span (max − min) of the cumulative sum of (supply − demand), reported in hours of mean load. *Diurnal* storage isolates the average-day cycle (batteries); the larger *seasonal* residual (weeks) is reported separately and is not a battery duty — it is met by firm hydro and seasonal utilisation flex. **Routable coincidence** is Σ min(supply, demand)/Σ demand: the fraction of demand met directly by coincident clean supply for a load free to follow the surplus within the day.

**Headline results.** Diurnal peak-to-mean: single solar site 2.64 → balanced portfolio 1.27 → +hydro 1.12 (demand 1.33, "total" scenario, empirical kernel). Diurnal storage: 9.2 h → 1.5 h (6.2× reduction); biggest-resources-only 2.9 h. Routable coincidence: 0.65 → 0.90 → 0.93.

## S3. Chip constraint (M3)

Parameters (central; ranges in code): facility-level power 2.0 kW (1.7–2.7) per high-end accelerator; all-in cost $50k (system) / $30k (chip); global high-end accelerator output ≈ 5×10⁶ yr⁻¹ in 2025 (≈3.76M data-centre GPUs in 2023), scaling ~1.35×/yr with CoWoS packaging capacity; Yarlung reference cost $167B. Continuous-equivalent compute of the portfolio = PWh yr⁻¹ × (10¹⁵/8760/10⁹) GW ≈ 133–257 GW. Accelerators to fill C GW = C×10⁶/power. Deployable GW yr⁻¹ at output share s = output × s × power / 10⁶. Years-to-fill = target / deployable. Results (20% share): 2.0 GW yr⁻¹ deployable; 10 GW in ~5 yr; 60 GW in ~30 yr (~30M accelerators, ~$1.5T, ~9× the dam); full portfolio ~66–129 yr; cumulative 2025–2035 ≈ 149 GW.

## S4. Limitations of the methods

- The demand envelope's diurnal *shape* is now empirically fitted to real hourly web-activity data (Wikimedia pageviews — a human-activity proxy, not measured AI inference; see S2), and the region *weights* are estimated from 2025 usage data (Anthropic Economic Index, Similarweb, OpenAI/NBER, China National Data Bureau; S2) — both remain order-of-magnitude. The qualitative results (global demand far flatter than any single region; portfolio diurnal storage ≪ single site; ≈ 90%/93% coincidence) are robust to the scenario choice (consumer vs total-incl-China); exact percentages are illustrative.
- ERA5 single-year (2023) profiles omit inter-annual variability; seasonal residual storage is therefore a lower bound on a multi-year worst case.
- Strandable-energy ranges are curated from secondary sources and should be replaced/peer-checked against primary project data before submission.
- GPU output and packaging-capacity figures move fast; treat as ranges and update at submission.
